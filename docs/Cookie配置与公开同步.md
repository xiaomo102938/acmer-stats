# Cookie 配置与公开同步

更新日期：2026-11-04。

## 访问策略

牛客填写个人主页链接或数字 UID 后，优先读取公开的竞赛站练习 AC 记录。即使用户保存过 Cookie，公开请求也不携带它。只有返回登录要求、401 或 403 时，才在已配置 Cookie 的情况下重试一次；分页后沿用本次已确认需要的会话模式。429 限流、验证码页和无法识别的数据不进行自动循环重试。

QOJ 当前同步可访问的 AC 提交列表，需要登录 Cookie。尚未配置时，账号按钮直接显示“配置 Cookie”，点击后定位到编辑表单。牛客未填写 UID 时同样显示“填写 UID”。支持 nowcoder.com、www.nowcoder.com 或 ac.nowcoder.com 的受支持主页路径，拒绝其他域名和无法识别的链接。

同步仍由用户主动点击触发，不是后台定时任务。配置一次 Cookie 后可以重复使用，直到平台会话过期；失效时提示更新凭据，已有数据不清空。

## 操作步骤

1. 牛客先填写个人主页链接或数字 UID 并保存，尝试公开同步，不预先要求 Cookie。
2. QOJ 在浏览器正常登录，按 F12 打开开发者工具，选择“网络 / Network”并刷新站点页面。
3. 选择该平台主页面请求，在“请求标头 / Request Headers”内找到 Cookie。复制完整的 name=value; name2=value2 内容，不包含 Cookie: 前缀，也不要使用 Set-Cookie 响应头。
4. 在本机设置页编辑对应账号，粘贴 Cookie 并保存，再点击同步。多个 QOJ 账号分别核对配置状态和返回结果。
5. 编辑时留空表示保留原 Cookie，勾选清除表示删除已保存的 Cookie。不能同时勾选清除又填写新 Cookie，以免产生歧义。

Cookie 仅在本机服务端加密保存，不返回到页面，不放入文档、Git 或聊天消息。此处配置的是平台登录会话，不收集平台密码。

## QOJ 实测限制

2026-11-04，两个账号均已保存加密 Cookie。服务器请求 QOJ 时均返回 HTTP 403、cf-mitigated: challenge 和 Just a moment 标题，证明请求在 Cloudflare 浏览器验证处被拦截，尚不能验证登录会话有效性，也未导入 QOJ 数据。程序单独提示浏览器验证，不将其误报为 Cookie 已失效，不自动反复重试或处理验证码。两个同平台账号应依次同步；服务端在接收请求时拒绝同平台并行同步，避免将其记录成一次平台采集失败。
