# Cookie 配置与公开同步

更新日期：2026-11-04。

## 访问策略

牛客填写个人主页链接或数字 UID 后，优先读取公开的竞赛站练习 AC 记录。即使用户保存过 Cookie，公开请求也不携带它。只有返回登录要求、401 或 403 时，才在已配置 Cookie 的情况下重试一次；分页后沿用本次已确认需要的会话模式。429 限流、验证码页和无法识别的数据不进行自动循环重试。

QOJ 当前同步可访问的 AC 提交列表，需要登录 Cookie。尚未配置时，账号按钮直接显示“配置 Cookie”，点击后定位到编辑表单。牛客未填写 UID 时同样显示“填写 UID”。支持 nowcoder.com、www.nowcoder.com 或 ac.nowcoder.com 的受支持主页路径，拒绝其他域名和无法识别的链接。

同步仍由用户主动点击触发，不是后台定时任务。配置一次 Cookie 后可以重复使用，直到平台会话过期；失效时提示更新凭据，已有数据不清空。

## 操作步骤

1. 牛客先填写个人主页链接或数字 UID 并保存，尝试公开同步，不预先要求 Cookie。
2. QOJ 在浏览器正常登录，按 F12 打开开发者工具，选择“网络 / Network”并刷新站点页面。
3. 选择该平台主页面请求，在“请求标头 / Request Headers”内找到 Cookie。复制完整的 name=value; name2=value2 内容，不包含 Cookie: 前缀，也不要使用 Set-Cookie 响应头。
4. 在本机设置页编辑对应账号，粘贴 Cookie 并保存，再点击同步。多个 QOJ 账号分别核对配置状态和返回结果。
5. 编辑时留空表示保留原 Cookie，勾选清除表示删除已保存的 Cookie。不能同时勾选清除又填写新 Cookie，以免产生歧义。

Cookie 仅在本机服务端加密保存，不返回到页面，不放入文档、Git 或聊天消息。此处配置的是平台登录会话，不收集平台密码。

## 牛客实测

数字 UID 891521540，对应 xiaomo102938。2026-11-04 公开同步导入 304 条 AC 提交、294 道通过题，未使用 Cookie；题数与公开主页的已通过题数一致。这不等于全部 809 次提交，失败提交不在当前 AC 采集范围内。

实测修复了一个误判：普通牛客页面脚本包含 useNeteaseCaptcha 变量，旧逻辑只要全文出现 captcha 就中断。本次根据挑战页标题、挑战表单和无记录表格时的正文判断拦截，不把验证码组件库名称当作验证码挑战，也不会自动处理真实验证码。

## 验证

新增测试覆盖主页链接规范化、相似恶意域名拒绝、公开请求不发送 Cookie、登录后才回退到 Cookie、缺少或过期会话提示、429 不触发凭据重试，以及正常页面含验证码脚本时仍解析真实记录。配合真实牛客同步与重复同步检查，确保配置流程和入库幂等。

## QOJ 实测限制

2026-11-04，两个账号均已保存加密 Cookie。服务器请求 QOJ 时均返回 HTTP 403、cf-mitigated: challenge 和 Just a moment 标题，证明请求在 Cloudflare 浏览器验证处被拦截，尚不能验证登录会话有效性，也未导入 QOJ 数据。程序单独提示浏览器验证，不将其误报为 Cookie 已失效，不自动反复重试或处理验证码。两个同平台账号应依次同步；服务端在接收请求时拒绝同平台并行同步，避免将其记录成一次平台采集失败。

## QOJ 网络路径修复

后续对照本机 OJ Insight 0.10.5 的日志，确认 ai_nuo 成功新增 307 条记录。Windows 配置了本机 HTTP 代理，而本站默认 Node fetch 未使用该代理。使用同一 Cookie、本站 User-Agent 经该代理请求，返回 HTTP 200 并成功解析记录。此前 403 仅是直连路径的结果，不代表此 Cookie 方案不可用。

新增可选环境配置 QOJ_PROXY_URL，填写 HTTP(S) 代理地址后，仅 QOJ 采集使用 Undici ProxyAgent；留空仍直连。修改后重启服务。本机代理软件必须运行；不修改 Windows 全局代理，也不将 Cookie 发送到其他平台。正式部署应按服务器实际网络选择配置。

QOJ_PROXY_URL=system 时，每次开始同步都会重新读取 Windows 当前 ProxyEnable/ProxyServer；关闭系统代理后下一次同步恢复直连，开启后使用当前地址。同步过程中不切换出口。其他操作系统在 system 模式下直连，应改填明确代理地址。PAC 自动脚本暂不解析。本站 QOJ 请求同时采用 HTML 页面兼容请求头；仅使用代理但保留旧请求头，实测仍可能被拦截。该策略不保证所有网络下都可访问。

QOJ 分页上限提高至 100 页（通常每页 10 条）；达到上限会明确提示历史未完整覆盖。牛客仍为 20 页。代理地址只保存在本机 .env，示例文件不包含本机端口或凭据。

本机另启用 QOJ_HTTP_TRANSPORT=curl，使用 Windows 自带 curl.exe 的原生 HTTP 客户端处理 QOJ 请求，作为 Node 客户端兼容选项；留空使用 Node fetch。Cookie 经子进程标准输入传入配置，不出现在命令行参数中，不调用 shell，不跟随重定向，保留 TLS 证书校验及 20 秒超时。只作用于 QOJ。关闭或切换代理后会按下一次同步开始时的系统设置访问，原 Cookie 是否仍有效由站点判断。

新增测试验证系统代理开关、按协议代理地址选择，以及原生客户端请求头传递、UTF-8 正文与重定向不跟随。全部 35 项测试通过。

实测结果：ai_nuo 经代理及原生 HTTP 客户端成功导入 307 条 AC 提交、271 道题；307 条提交与同机 OJ Insight 0.10.5 当次同步日志一致。没有将该结果视为全部失败提交或全部历史尝试次数。
