# 题型标签与能力参考值

所有已识别的同义标签使用统一的英文键保存，显示为“中文 / English”。例如 dp、dynamic programming、动态规划均保存为 dp，显示为“动态规划 / Dynamic Programming”。同步写入经过同一份 tags.js 字典，不会因为源平台语言不同而重新创建同义标签。未识别的标签保留原意，不进行模糊匹配；图论、图匹配、DFS 等相关但不等价的分类分开保存。

旧标签合并时先将题目关联取并集，随后删除多余标签。题目同时带有两个同义标签时，合并后只有一个关联，不重复计分。006_tag_ability.sql 包含现有字典的数据库迁移快照及事务合并；scripts/normalize-tags.mjs 可单独重复运行，处理后来从外部 SQL 导入的旧标签。应用侧统一逻辑位于 src/backend/tags.js。

## 能力参考值

对每个用户、平台和题型分别计算：

1. 只选最终已通过的题目，不使用提交通过率。
2. 只选具有有效数字难度和明确来源的题目；CF 使用官方 rating，AT 使用 AtCoder Problems 社区估计值，互不混算。
3. 每道题在该题型下只计一次，同一题可参与不同题型的计算。
4. 按难度降序选最高的 25 道；若不足 25 道则选全部，并标明样本不足。
5. 对入选难度取算术平均，保留一位小数。

达到 25 道显示“满25题”，不足 25 道显示“样本不足”，没有有效评分显示“暂无有效评分”。无评分不按零分处理。界面展示有效评分题数、入选数、分数范围，并可点击均值展开入选题单。满样本优先排列，未满样本的高均值仅作为暂定值展示。

这个指标描述已完成题目的历史难度上沿，不是官方 rating 或即时比赛表现的估计。长期刷更难题会逐步替换原来的低分入选题；满样本后新刷低难度题不会拉低均值。题目官方或社区难度被重新评估时，参考值也会随之更新。未满 25 道时，一两道难题仍可能使暂定均值偏高，因此不能忽略样本状态。

## 数据库与接口

- v_tag_stats 保留题型尝试量、通过量和描述性的题目通过率，移除旧的擅长/薄弱判定。该通过率不再用于能力评分。
- v_tag_ability 使用 ROW_NUMBER 按用户、平台、题型选择最高 25 道，并输出评分、范围与样本状态。
- GET /api/dashboard 返回 tagAbility 数据。
- GET /api/tags/:id/ability?platform=Codeforces 返回最多 25 道入选题目，筛选规则与视图一致。
- sp_tag_rank 调整为双语标签及基础数量统计，不再输出旧掌握度。

## 验证

npm test 检查中英文别名、双语格式及不应误合并的细分类别。

node --env-file=.env tests/sync-database.mjs 在独立测试数据库检查关系取并集、同题去重、top-25 均值、无评分和失败题排除、添加高难度/低难度题的影响、平台隔离以及重复迁移。

node --env-file=.env tests/tag-ability-api.mjs 将所有线上平台题型评分与原始记录在 JavaScript 中独立计算的结果对比，同时核对入选题单与均值。
