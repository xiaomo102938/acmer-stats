## 项目简介

面向 ACM 选手的个人刷题数据分析网站。集中记录在 Codeforces、洛谷、AtCoder、LeetCode 等平台的刷题数据，提供多维度统计分析与可视化展示：各平台刷题量、题型能力参考（最高25题难度均值）、难度分布、月度趋势、连续打卡等。

特色功能：绑定平台公开用户标识，在设置页主动触发后台同步。需要会话的平台可保存 AES-256-GCM 加密 Cookie；不收集平台登录密码。支持 CF 尺度的跨平台题型能力参考、年度热力图与明暗主题。

## 技术栈

- 前端：Vue 3 + ECharts
- 后端：Node.js（Express）
- 数据库：MySQL 8.0
- 数据采集：Node.js fetch + Cheerio，公开接口与平台适配器
- 版本控制：Git + GitHub

## 本地运行网站

要求 Node.js 20.19+ 或 22.12+（推荐当前 LTS）、npm、正在运行的 MySQL 8.0。

1. 在项目根目录执行 npm install。
2. 复制 .env.example 为 .env，填写数据库密码；本机已配置，.env 不提交 Git。
3. 执行 npm run build。
4. 执行 npm start，访问 http://127.0.0.1:3000。

开发前端时保持后端运行，另开终端执行 npm run dev，Vite 会将 /api 代理到本机 3000 端口。

当前实现：Vue 3 + ECharts 只读统计看板，Express + mysql2 连接池接口 GET /api/dashboard，展示总览、平台统计、题型能力参考、月度趋势、难度分布和最近 8 条记录。仅监听本机地址。记录编辑、账号管理、自动同步尚未实现。

验证：前端生产构建通过；HTTP 首页返回 200；接口返回 14 道题、11 道通过、78.6% 通过率、4 个平台、7 个标签，与当前数据库一致；已在浏览器检查页面和图表。

## 账号管理与同步

侧栏“设置”进入账号录入与同步面板。支持同平台多账号、编辑 Cookie、手动同步和解绑。Codeforces 与 AtCoder 已用本人账号完成真实同步及重复同步验证；QOJ 需要登录 Cookie，牛客需要数字 UID，力扣只读取公开最近 AC。不同平台的数据范围、密钥配置、迁移方法和测试命令详见 docs/平台账号与同步说明.md。

已同步题目显示各平台原生难度，CF 使用官方 rating，AtCoder 使用 AtCoder Problems 社区估计值；缺失时显示“暂无公开难度”。当前保留初始示例数据，不清空原记录。本机模式没有公开部署用的用户登录功能。

## 页面结构

- 数据简览（#overview）：核心总量、近 7 天表现与难度饼图。
- 详细分析（#analysis）：月度趋势、难度分布、平台统计与完整题型能力参考。
- 最近记录（#records）：最近更新的 8 条题目汇总记录。
- 设置（#settings）：主题偏好及平台账号管理、同步。

导航高亮与地址保持一致，支持刷新和浏览器前进后退；旧的 #trends、#tags、#recent、#accounts 链接会自动转到新页面。切换时只渲染当前页，销毁离开页面的图表；账号轮询仅在设置页运行。

近 7 天按数据库当天及之前 6 个自然日统计同步明细，缺失日期补零。提交次数和 AC 次数按提交计数，尝试题目跨天去重；不包含原有示例和手工记录。只提供 AC 数据的平台不具有完整失败提交。时间范围查询已新增索引，已有数据库执行一次 sql/migrations/004_daily_activity_index.sql，本机已应用。

验证：生产构建、Vue 模板编译、浏览器四页导航高亮/前进后退/刷新、旧链接兼容、设置中的主题切换均通过。node --env-file=.env tests/daily-activity.mjs 可将近 7 天统计与原始提交明细做只读比对。

## 原生难度修复

Codeforces 提交中的 problem.rating 已有保存，现已在题目记录中正确显示为 CF 分数。AtCoder 补充读取 AtCoder Problems 的 problem-models.json，并按维护者的 clipDifficulty 公式处理低于 400 的估计值，显示 AT 分数及估计标记。AtCoder 的比赛题目得分与估计难度是不同指标，不相互替代。

难度饼图可按平台切换，数字难度按 400 分分段，不混合各平台尺度。新字段 difficulty_source 记录来源。难度元数据每个进程缓存 6 小时，数据源失败时保留原有值；每次同步同时补全已有题目的元数据，避免增量同步遗漏旧题难度。

现有数据库执行一次 sql/migrations/005_native_difficulty_source.sql；本机已应用并完成历史回填。也可执行 node --env-file=.env scripts/refresh-difficulties.mjs，仅更新难度与题目名称，不新增提交或改变刷题计数。部分题目没有官方 rating 或社区估计值，会如实显示缺失。

数据源：[CF 官方对象定义](https://codeforces.com/apiHelp/objects#Problem)、[AtCoder Problems API](https://github.com/kenkoooo/AtCoderProblems/blob/master/doc/api.md)、[低难度显示公式](https://github.com/kenkoooo/AtCoderProblems/blob/master/atcoder-problems-frontend/src/utils/index.ts)。

## 年度刷题热力图

数据简览增加 GitHub 风格的年度日历方格，可切换年份、平台及指标（默认每日去重 AC 题数，也支持提交次数和尝试题目）。鼠标悬停显示日期详情，点击或键盘聚焦后在图下保留详情；键盘方向键可在日期间移动。窄屏在图内横向滚动，不撑宽页面。未来日期留空，闰年保留 2 月 29 日。

每个方格按当前指标使用固定颜色档位：0、1–2、3–5、6–9、10 及以上。AC 题数当日去重，同题跨天分别计数；年度合计按天相加，不代表全年唯一题数。仅使用已同步的提交明细，不把示例或手工汇总日期当成真实每日提交活动。缺失平台历史不代表当天未练习。

GET /api/activity?year=2026 提供按日期和平台分组的数据，使用现有 submitted_at 索引查询年份范围。前端以 CSS Grid 渲染至多约 54 周的静态方格，不新增图表依赖，不使用持续动画或轮询。

验证：node --test tests/heatmap.test.js 检查闰年、周对齐、跨平台汇总、未来日期和色阶；node --env-file=.env tests/activity-api.mjs 将所有历史年份数据与原始提交逐条比对。生产构建及浏览器年份/平台筛选、点击日期与键盘导航通过。
